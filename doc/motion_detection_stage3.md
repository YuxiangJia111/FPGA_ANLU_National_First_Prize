# 阶段三：复用灰度 BRAM 的运动区域检测

日期：2026-10-15。阶段 1、2 已获用户初步上板认可；本阶段在 TRACK 模式中叠加独立的硬件帧差检测。尚未实现方向箭头，也未用帧差改变数字目标的运动状态。

## 1. 本版显示

- 原图、绿色跟踪框、黄色 ID 和中心坐标维持阶段 1、2 的行为。
- 运动区域显示黄色小块轮廓，轮廓厚度 2 像素，通常每块覆盖 48×48 原图像素。右侧、底部最后一块按 ROI 边界截短。
- 帧差检测不依赖数字框或 CNN 数字，手和其他物体在检测区域内移动也能触发。
- 检测范围沿用现有灰度缓存 ROI：**X=198～1022，Y=18～702**，并非整幅 1280×720。区域外不会产生帧差提示。
- 数字框边框及其黄色 ID、延迟 HUD 和左侧面板的显示优先级高于运动轮廓。

左侧增加一行状态：

| 状态 | 含义 |
| --- | --- |
| DIFF:WAIT | 尚无完整可用的参考结果，或本帧存在参考读口冲突/数据不完整 |
| DIFF:READY | 参考有效，黄色轮廓表示达到门限的运动块；静止时可以没有轮廓 |
| DIFF:LIGHT | 超过 75% 的 ROI 采样点发生明显变化，本帧抑制运动轮廓 |

LIGHT 是全局变化的启发式提示，不能证明原因一定是灯光。摄像头移动或占据大部分画面的物体变化，也可能触发。

## 2. 缓存复用方式与时间定义

原有两个灰度 bank 由采集、区域分析和 CNN 裁剪共享；它们不保证逐帧交替。直接将两个 bank 当成相邻两帧，会引入错误的时间对应和端口争用。

本版在原采集时序不变的前提下，在采样边沿读取**当前写入 bank 的相同地址旧值**，下一边沿执行原有的已寄存写入。旧像素与当前像素流水对齐后进入帧差模块。因此：

- 不新增整帧 RAM，继续使用现有 4 bit 灰度数据。
- 参考是该 bank 上一次完整采集的图像，属于**间隔帧差**，不是严格的相邻视频帧差。
- 同一 bank 连续采集时，参考通常来自前一采集帧；bank 轮换时，参考可能更早，具体间隔由原有调度决定。
- 每个 bank 首次使用时只建立历史有效性，不将未初始化 RAM 内容当作运动。切换模式后重新建立参考，进入 TRACK 后允许等待几个采集帧。
- 停止后，旧参考对应的变化轮廓可能再保留几个帧；它不是目标持续跟踪框。

读口只在采集采样边沿借用当前写入 bank。CNN 忙时，其选定 bank 的读地址始终保留；若异常情况下 CNN 与采集指向同一 bank，帧差放弃该参考，本帧结果标记 WAIT，不抢占 CNN 端口。

原灰度/二值写使能、写数据、写地址、bank 轮换、连通区域分析和 CNN 调度逻辑均未改动。`digit_multi_bbox.v` 的局部改动限于预读地址选择、历史有效性和数据旁路接口。未手工修改生成 IP，也未修改 DDR、ISP 或 CNN 核心。

## 3. 帧差与噪声过滤

使用现有 SAMPLE_STEP=3 的 ROI 灰度采样，共 275×229 点，每点 4 bit：

```text
abs(当前灰度 - 同 bank 历史灰度) >= DIFF_THRESHOLD
                         ↓
              每 16×16 个采样点分块统计
                         ↓
                达到数量门限的块有效
                         ↓
              完整帧结果在下个帧起点发布
```

默认参数位于顶层 `u_frame_diff_motion`：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| DIFF_THRESHOLD | 3 | 4 bit 灰度差门限；约对应 8 bit 灰度量级 48 的变化 |
| MIN_CHANGED | 16 | 完整块至少需要 16 个变化采样点，共 256 点 |
| BLOCK_SHIFT | 4 | 每块边长 2^4=16 个采样点 |

更改灰度差门限时一般在 1～15 内调整；减小后对低对比度移动更敏感，也更容易受噪声和曝光变化影响。KEY1 仍只调节原数字检测亮度阈值，KEY2 仍只调节数字连接间隔，不调节本模块。

最后一列、最后一行和右下角块按有效面积降低门限，默认分别为 3、5、2 个变化点。只要块至少有两个采样点且 MIN_CHANGED>=2，就不允许单个变化点触发。

全局变化点超过总采样数的 75% 时，抑制整幅运动块结果。该门限目前为 RTL 内的常量比较，不涉及逐像素除法。该功能不能消除所有光照扰动，仍建议固定摄像头、稳定照明。

资源主要增加一行 18 个小计数器、270 bit 工作/待发布/显示掩码和显示译码寄存器；没有新增图像缓存。实际 LUT、寄存器、BRAM 和时序变化以用户综合、布局布线结果为准。

## 5. 上板操作与验收

1. 重新加载 `.al`，确认两个新增模块在源文件列表，顶层仍为 `design_top_wrapper`。
2. 综合后检查资源，尤其确认没有额外整帧 RAM；再查看布局布线时序，关注灰度 RAM 读地址和 OSD 新路径。助手未执行综合、布局布线或下载。
3. 下载后关闭 SW4 强制原图，默认 GRAY 下按 KEY3 一次进入 TRACK。等待 `DIFF:READY`。
4. 按下表逐项观察。黄色 ID 与运动轮廓颜色相同，但 ID 是文字；绿色框仍表示跟踪目标，不表示已确认运动。

| 测试 | 操作 | 预期 |
| --- | --- | --- |
| 静止 | 固定摄像头，数字牌静止 | ID 与坐标正常，没有持续大面积黄色轮廓 |
| 数字牌移动 | 在 ROI 内缓慢移动一张牌 | 变化附近出现黄色小块，原跟踪 ID 尽量保持 |
| 非数字移动 | 在 ROI 内晃动手或其他物体 | 即使没有数字框，也出现运动提示 |
| 停止 | 停止移动并等待参考更新 | 黄色轮廓消失，数字框及坐标继续显示 |
| 区域位置 | 分别在 ROI 左右、上下移动 | 提示位置对应实际变化，不发生横向/纵向错位 |
| 区域外 | 只在 X<198 等 ROI 外移动 | 不要求出现运动提示 |
| 多目标/CNN | 多张数字牌移动，再切回原识别和 PREVIEW | 跟踪、CNN 标签及裁剪预览没有明显回退 |
| 全局变化 | 明显改变整体照明后等待稳定 | 大范围变化时可能短暂 LIGHT，稳定后恢复 READY |
| 模式重入 | 退出 TRACK，再进入 | 重新建立参考；无旧运动块残留 |

帧差可能只突出数字笔画/物体边缘的变化，不能保证黄色区域覆盖整个物体。当前帧差与跟踪独立，尚未输出移动数字牌数量或方向箭头。

脚本新增依赖本机安路仿真库，默认 `D:\Anlogic\sim_release`，可用 `-AnlogicSimRoot` 指定。真实 RAM 测试需加载厂商 `PH1P_PHY_GSR` 全局模块，脚本已处理。测试输出继续放在被忽略的 `sim/.tracking_work/`。
