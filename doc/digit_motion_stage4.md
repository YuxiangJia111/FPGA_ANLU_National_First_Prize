# 阶段四：数字牌八方向运动箭头

日期：2026-10-15。本版在已验证的 TRACK 模式、ERAM 跟踪和帧差提示之上，新增由目标坐标位移驱动的方向箭头。尚未执行新的综合、布局布线或上板验证。

## 1. 最终显示与本阶段边界

- 保留原图、绿色数字候选框、黄色跟踪 ID、中心坐标和黄色帧差块。
- 移动目标的框旁显示橙色箭头（RGB FF8000），支持右、右下、下、左下、左、左上、上、右上。
- 采用固定 32×32 像素箭头图形，不使用箭头长度表示速度。
- 优先放在框右侧，间隔 8 像素；靠近屏幕右边界时改放在框左侧，垂直位置限制在屏幕范围内。若与右上角延迟 HUD 重叠，则下移到 HUD 下方。
- 停止后经过短暂保持，隐藏箭头。新目标、模式重入和漏检后恢复都先建立参考，不立即显示方向。
- 多个目标分别保留状态。箭头窗口重叠时，低 ID 的窗口优先。

本阶段箭头仅由跟踪坐标判断，**未与帧差结果联合确认**。黄色帧差轮廓与橙色箭头可以独立出现；例如手移动会产生帧差，但不一定有数字牌方向箭头。绿色框也尚不因运动改变颜色，联合确认留在阶段五。

ID 仍是跟踪编号，不是 CNN 识别数字。摄像头需固定；目标交叉、框合并/拆分或错误匹配仍可能导致身份和方向错误，本阶段未增加外观重识别。

## 2. 平滑、位移窗口与停止逻辑

每次获得有效匹配的目标中心后，使用：

```text
平滑中心 = (上一平滑中心 + 当前原始中心 + 1) >> 1
```

原始检测框、中心坐标和 BCD 显示保持原行为；平滑仅用于方向判断。默认每 4 次有效目标更新，比较平滑中心与参考中心，计算 `abs(dx)+abs(dy)`。

- 静止状态下，位移达到 8 像素才启动箭头；未达到时保留参考中心，允许慢速移动跨多个窗口累积。
- 已显示箭头时，窗口位移大于 3 像素就更新方向并继续显示；否则累计安静窗口。
- 连续 2 个安静窗口后隐藏箭头。移动状态下每个窗口更新参考中心。
- 漏检期间直接隐藏箭头；保留期限内恢复原 ID 时也重新建立运动参考，避免把遮挡期间的跳变解释为方向。

方向由位移符号和两轴相对大小确定：若一轴至少为另一轴的 2 倍，则判为水平或竖直，否则判为斜向。无需角度、乘法器或除法器。

所有时间参数按**检测结果更新次数**计算，不是固定毫秒，也不是 CNN 批次。停止后的实际保持时间还受平滑残余、检测更新频率和下一显示帧提交影响。

参数位于顶层 `u_digit_motion_tracker`：

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| HISTORY_INTERVAL | 4 | 每几次有效匹配更新判断一次位移，范围 1～15 |
| START_DISTANCE | 8 | 启动箭头的曼哈顿位移门限，单位为原图像素 |
| STOP_DISTANCE | 3 | 移动状态下视为安静窗口的位移上限 |
| STOP_CONFIRM | 2 | 连续多少个安静窗口后隐藏箭头，范围 1～15 |

应保持 START_DISTANCE > STOP_DISTANCE。降低启动/停止门限可增强慢速响应，但会增加框抖动误触发。KEY1/KEY2 仍调节原检测阈值和连接间隔，不改变这些参数。

## 3. 资源与 ERAM 复用

**无需重新生成 IP，也未增加新的 ERAM 实例。** 当前生成模块仍为 `digit_tracker_state_ram_adapter`，16 bit×256、NOREG、公共时钟，直接由跟踪器实例化。

原 0xC0～0xFF 区域用于 8 个 ID 的方向历史，每个记录间隔 8 字，仅用前 5 字：

| 字偏移 | 内容 |
| --- | --- |
| 0 | 平滑中心 X，低 12 bit |
| 1 | 平滑中心 Y，低 12 bit |
| 2 | 位移参考中心 X，低 12 bit |
| 3 | 位移参考中心 Y，低 12 bit |
| 4 | bits[2:0] 方向、bit[3] 显示状态、bits[7:4] 窗口计数、bits[11:8] 安静窗口数 |
| 5～7 | 保留 |

历史、检测记录的原格式不变。待显示区域的中心 X 字（偏移 4）低 12 bit 仍是原始中心，高 4 bit 改为 bit[15] 箭头状态、bits[14:12] 方向。该状态与框和坐标一起在消隐期预读，下一帧生效。

方向编码：0=右、1=右下、2=下、3=左下、4=左、5=左上、6=上、7=右上。

运算复用现有中心加法与绝对差数据通路；新增少量串行状态和单目标工作寄存器，不建立 8 组分布式历史坐标数组。像素显示端 8 个目标共用一个箭头图形计算器，通过两级流水对齐原有视频。

仍会增加控制逻辑、图形窗口译码及放置寄存器。实际 Slice、LUT、seq 和时序变化必须通过用户重新综合和布局布线确认。

## 4. 修改文件

- `digit_motion_tracker.v`：在现有 ERAM 中保存方向历史，增加平滑、八方向、启动/停止门限和箭头输出。
- 新增 `digit_motion_arrow_osd.v`：放置与裁切、8 个目标窗口选择、共享图形、两级流水。
- `design_top_wrapper.v`、`display_top.v`、`hdmi_mixer.v`：局部传递箭头有效位/方向，在 HDMI 输出叠加橙色箭头。
- `.al` 已加入新箭头 RTL。现有生成 IP 文件、DDR、ISP、摄像头和 CNN 核心未修改。

显示优先级：延迟 HUD、左侧面板、框与数字标签优先；橙色箭头覆盖黄色帧差块轮廓。非 TRACK 模式不显示箭头。

## 5. 上板验证顺序

1. 重新加载 `td_project/camera_to_dsi_display.al`，确认 `digit_motion_arrow_osd.v` 已加入源文件清单，保留当前 RAM IP。
2. 综合并比较资源，再检查布局布线时序；优先关注跟踪器共享运算路径、RAM 读出和新增图形选择路径。
3. 下载后关闭 SW4 强制原图，默认 GRAY 下按 KEY3 一次进入 TRACK。
4. 用固定摄像头、白底黑字数字牌，按下表检查。先单牌，再两个分离目标，最后增加目标数量。

| 测试 | 预期 |
| --- | --- |
| 新牌静止 | 建立框、ID 和坐标，暂不显示箭头 |
| 左右/上下移动 | 稳定移动一小段后出现正确水平/竖直箭头 |
| 四个斜向 | 出现对应斜向箭头；接近方向分界时允许切换 |
| 缓慢移动 | 位移可累积到启动门限，箭头不要求紧邻两帧就出现 |
| 停止 | 短暂保持后箭头消失，框和坐标继续显示 |
| 小幅静止抖动 | 不应频繁出现方向箭头 |
| 反向移动 | 持续反向移动后方向跟随更新 |
| 两牌独立移动 | ID 对应的箭头分别更新；停止其中一牌不清除另一牌箭头 |
| 短暂漏检/遮挡 | 隐藏箭头；恢复 ID 后重新积累参考 |
| 模式重入 | 不继承上次的箭头 |
| 位置与裁切 | 箭头跟随框，靠边保持在画面内；现有 ROI 限制实际可达位置 |
| 旧功能 | 黄色帧差提示、CNN、PREVIEW、LCD 和原各模式保持正常 |

箭头方向是图像坐标中的方向，不表示真实世界距离或速度。摄像头整体晃动可能同时触发多个目标方向，不能视为相机运动补偿。
