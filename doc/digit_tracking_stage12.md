# 数字牌跨帧跟踪：阶段 1、2 上板说明

日期：2026-10-15。仅完成跟踪和信息标注，尚未加入帧差、运动状态或方向箭头。

后续进展：阶段 1、2 已通过用户初步上板测试。阶段三现已实现独立帧差区域提示，当前版本的缓存复用、验证结果和上板步骤请另见 `motion_detection_stage3.md`；本文保留阶段 1、2 的版本说明。

## 1. 本版实现

- 新增 `111 / TRACK` 模式，在原图上绘制绿色检测框和黄色跟踪编号 1～8。
- 左侧 `TRACK N:n` 显示本次检测中实际可见的跟踪目标数。每个 ID 对应一组 `X:xxxx / Y:yyyy`，表示框中心的原图像素坐标，原点在左上角，X 向右、Y 向下。
- 跟踪 ID 与 CNN 数字是不同的信息。本模式框旁的黄色数字是 **ID**，不是 CNN 识别值。原模式仍使用原有 CNN 框和数字标签，CNN 推理继续运行。本版暂不把异步 CNN 标签绑定到新跟踪 ID，以免将旧裁剪结果贴到移动后的其他目标上。
- 使用 `digit_multi_bbox` 发布的整组框，不按 CNN 批次更新跟踪，也不将检测框槽位当作目标身份。
- 逐周期搜索全体候选对，优先分配距离最近且尺寸相近的一对，再排除已分配目标继续搜索；不需要乘法、除法或并行排序网络。
- 结果和坐标十进制转换完成后，统一在下一视频帧边界发布。因此新增约一个显示帧的发布等待，检测器本身也有分析延迟。
- 首次出现的目标按空闲 ID 分配；ID 不是永久编号，释放后可以复用。

## 2. 缓存与修改边界

当前检测器已有两个 `4 bit × 65536` 灰度帧 RAM bank，缓存 ROI 内按 SAMPLE_STEP=3 降采样的灰度，供 CNN 裁剪读取。本阶段只消费检测坐标，不新增图像 BRAM，也不改变灰度 RAM 的端口、读写地址或 bank 管理。后续帧差阶段再确定双 bank 的可复用读写窗口。

未修改 DDR、ISP、摄像头配置和 CNN 核心。新增：

- `user_source/hdl_source/digit_motion_tracker.v`：目标匹配、短暂漏检保留、超时释放、中心计算、串行 BCD 转换、帧边界发布。
- `user_source/hdl_source/digit_track_osd.v`：左侧 ID 与坐标面板；预先一级寄存字形输出，与 mixer 原有像素流水对齐。

局部接入：`design_top_wrapper.v`、`control_top.v`、`display_top.v`、`hdmi_mixer.v`、`lcd_mode_display.v`。Tang Dynasty `.al` 已加入两个新增 RTL 文件，测试台不加入综合。

## 3. 操作

1. 在 Tang Dynasty 中重新加载 `td_project/camera_to_dsi_display.al`，确认两个新增模块已出现在源文件列表，顶层仍为 `design_top_wrapper`。
2. 综合、检查资源和时序，再完成布局布线和下载。助手未执行这些步骤。
3. SW4 关闭强制原图。默认 GRAY，按 KEY3 一次即可进入 TRACK；也可按 KEY4 经 BINARY、SOBEL、AUTO_EXP、EQUALIZE、PREVIEW 到 TRACK。
4. LCD 模式行应显示 `TRACK`，HDMI 左侧出现跟踪面板。
5. KEY1、KEY2 仍分别调节检测亮度阈值与连接间隔。SW1～SW3 不选择跟踪 ID，仍供原 PREVIEW 模式选框使用。

检测器现有 ROI 为 X=198～1022、Y=18～702；在此范围内摆放数字牌。检测依赖现有亮度阈值与数字笔画分割，建议固定摄像头、白底黑字、避免过强反光及手遮住数字。跟踪对象是检测器输出的候选框，尚未用 CNN 类别过滤。

## 4. 验证顺序与通过标准

| 顺序 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 遍历原有模式、数字识别和 PREVIEW | 视频、CNN 标签、裁剪预览和 LCD 维持正常 |
| 2 | TRACK 下放置单张数字牌并静止 | 一个绿色框，黄色编号与面板 ID 对应，坐标基本稳定 |
| 3 | 单牌缓慢向左右、上下移动 | ID 不变；右移 X 增大、下移 Y 增大；不显示箭头 |
| 4 | 放置两张相隔较远的牌，分别移动 | 各自 ID 保持，坐标与对应框一致，不跟随检测器排序换号 |
| 5 | 换成两张相同数字的牌 | 仍可分配不同 ID；本版匹配不依赖 CNN 数字 |
| 6 | 在离已有牌较远的位置加入一张新牌 | 分配空闲 ID，已有 ID 保持 |
| 7 | 短暂遮挡或漏检后在附近恢复 | 漏检期间框隐藏、坐标留空；保留期限内能匹配时恢复原 ID |
| 8 | 移走目标，等待超过 5 次检测结果更新后再加入 | 旧 ID 已释放，可分配并复用；不要求新牌继承旧身份 |
| 9 | 退出 TRACK 再进入 | 历史清空，重新分配 ID；面板不出现在其他模式 |

先验证单目标，再验证两个分离目标，最后增加到更多目标。最多支持 8 个保留中的 ID；短暂漏检的 ID 也占用名额。

## 5. 参数与限制

参数在顶层实例 `u_digit_motion_tracker` 中设置：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| MATCH_DISTANCE | 96 | 相邻两次检测中心的 `abs(dx)+abs(dy)` 上限，单位为原图像素 |
| SIZE_TOLERANCE | 64 | 框宽差及框高差各自允许的最大值，单位为原图像素 |
| MAX_MISSED | 5 | 连续缺失多少次检测结果后释放 ID；当前漏检计数器为 4 bit，调参范围 1～15 |

“检测更新次数”不等于摄像头帧数或 CNN 批次数；检测器未发布新结果时不递增漏检次数。漏检恢复时仍相对最后一次位置匹配，不扩大距离门限。

本版采用位置与尺寸匹配，没有外观特征或速度预测。快速跳动、框合并/拆分、两牌交叉、长时间遮挡可能丢失或交换 ID；不能将它描述为已经解决遮挡身份识别。先在目标分离场景验证，再按实测调整门限。
