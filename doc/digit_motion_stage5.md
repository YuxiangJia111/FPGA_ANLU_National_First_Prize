# 阶段五：移动数字牌联合确认与蓝框

日期：2026-10-16。用户已上板验收阶段四；本阶段实现完成后需重新综合、布局布线和上板验证。

## 显示行为

TRACK（111）模式中，静止或未确认移动的数字候选框保持绿色（00FF00）。坐标运动与框内帧差活动同时满足时，框变为蓝色（0000FF），并显示原有橙色八方向箭头（FF8000）。黄色帧差轮廓、ID 与坐标继续保留。箭头和蓝框使用同一有效掩码，并与框在消隐期预载、下一帧提交，避免有效视频内切换。

## 联合判断

1. 保留阶段四平滑、4 次更新位移窗口、启动 8 像素、停止 3 像素及 2 个安静窗口的坐标运动候选状态。
2. 每个有效目标串行扫描 18×15 个帧差块，检查活动块是否与当前检测框相交。块大小为原图 48×48 像素，最右、最下块按 ROI 裁切；至少一个有效活动块相交即可形成框内活动证据。
3. 框内活动出现后保持计数置 4，之后每次该目标有效更新递减。计数非零且坐标候选处于移动状态，才确认移动；这使不同节奏的帧差和位移窗口能够衔接。单次活动可用于当次及接下来的 3 次更新。
4. 当前对应帧的参考无效或属于全局光照变化时，立即撤销活动保持并隐藏蓝框/箭头；坐标历史继续更新。重新获得有效局部活动后可再次确认。
5. 漏检时隐藏目标；重新匹配、分配新 ID 或退出再进入模式，重新建立运动参考，不把缺失期间的跳变当作方向。停止后，坐标停止逻辑或活动计数到期均可撤销移动确认。

时间均按检测结果有效更新次数计算，不是固定毫秒。顶层 `REQUIRE_FRAME_DIFF=1`、`ACTIVITY_HOLD=4`（保持范围 1～15）。模块默认 `REQUIRE_FRAME_DIFF=0` 用于独立坐标回归和兼容验证，实际工程已开启联合判断。

## 检测框和帧差对应关系

不能直接用最新显示的黄色块判断旧检测框。`frame_diff_motion` 在采集结束后输出完成脉冲及本次结果；`digit_multi_bbox` 仅在接受同次采集进入分析时等待并取走它。帧差图及参考/光照标志随该次分析、待发布结果、帧边界输出一同传递。跟踪器在接收整批检测框时再同时快照这些信息，后续输入变化不影响正在计算的一批。

即使 CNN 占用对端 bank、检测分析较慢或某些采集未进入分析，也不会用更新帧的帧差替代旧框的证据。参考无效的采集仍可正常检测和跟踪，只不形成移动确认。面板 DIFF 和黄色轮廓展示最新帧差，蓝框按检测框所对应的采集结果判断，两者可能存在显示延迟。

帧差仍复用采集 bank 的历史灰度，属于间隔帧差，并非严格连续帧。ROI 仍为 X=198..1022、Y=18..702。

## 资源与文件

无需重建或新增 IP。既有 16×256 `digit_tracker_state_ram_adapter` 保持不变。每 ID 的历史字偏移 5 低 4 bit 存储活动保持计数，偏移 6、7 继续保留。方向候选与联合确认状态分开保存，显示记录的原箭头位现在保存联合确认状态。

框内活动使用一个串行扫描器，最多 8×270=2160 个扫描周期，另外有原跟踪、历史读写等开销。为保证同采集对应关系，新增 4 份 270 bit 元数据暂存（分析、待发布、框输出、跟踪快照，共 1080 bit）及少量标志/计数逻辑；不是新增灰度帧缓存。实际 Slice、LUT、寄存器和时序需以综合、布线报告为准。

修改 `frame_diff_motion.v`、`digit_multi_bbox.v`、`digit_motion_tracker.v`、`design_top_wrapper.v` 和 `hdmi_mixer.v`。没有新增需加入工程清单的综合 RTL。

## 上板验收顺序

重新加载原 `.al` 工程，保留当前 ERAM IP，综合后比较资源并检查布线时序，再下载进入 TRACK。固定摄像头，使用白底黑字数字牌。

| 操作 | 预期 |
| --- | --- |
| 放入静止数字牌 | 绿色框、ID、坐标；无箭头 |
| 只在旁边移动手，牌保持静止 | 可出现黄色帧差提示，牌保持绿色；若手影响分割导致框位移，仍可能误触发 |
| 持续水平、竖直、斜向移牌 | 短暂积累后蓝框与橙色对应箭头同时出现 |
| 缓慢移动 | 位移可跨窗口积累；帧差不足时可能保持绿色，可结合黄色块观察 |
| 停止移动 | 允许短时保持，随后恢复绿色、箭头消失 |
| 多牌分离，其中一牌移动 | 各 ID 分别确认，静止牌不应随另一牌变蓝 |
| 遮挡后重新出现 | 先恢复绿色并重新建立运动参考 |
| 大范围明暗变化 | 对被判定为全局变化的采集，不形成蓝框与箭头 |
| 退出后再进入 TRACK | 不继承上次的移动确认 |
| 切换原 CNN / PREVIEW 等模式 | 原功能和原框色正常 |

该方法采用块级重叠而非精确的框内逐像素统计。框外手部与数字处于同一活动块、框跳动或错误匹配时仍可能产生误确认；相机移动、目标交叉和合并也超出当前身份保持能力。
